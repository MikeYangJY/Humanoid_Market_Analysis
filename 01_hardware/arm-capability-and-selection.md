# 机械臂能力与选型：从六维能力到客户采购

[上游硬件](README.md) · [协作厂商供臂逻辑](arms-and-oem-sourcing.md) · [模型与控制](../02_models/README.md) · [跟踪指标](../04_tracking/metrics.md)

整理与技术资料核对日期：**2026-09-29**。本篇为选型与研究框架，聚焦完整机械臂及臂、手、传感器和模型之间的接口；不新增市场数量预测、盈利测算或估值，不对厂商做未经实测的排名。既有供货案例仍以[供臂专题](arms-and-oem-sourcing.md#evidence)标注的资料日期为准。

**核心判断：机械臂决定手能否到位、能否摆出合适姿态，以及接触物体后能否调整。研究供应商时，应从客户任务出发，将运动、负载、力控、末端适配、控制开放和机器人学习串成一条验证链，最终看任务表现和集成成本。**

本篇回答“什么样的机械臂适合什么任务”，[供臂专题](arms-and-oem-sourcing.md#sourcing)回答“由谁设计、谁制造、OEM为什么外购”。两者共同解释产品能力怎样影响采购，但技术适配本身不能证明中标、份额或复购。

<a id="framework"></a>

## 1. 六个维度分别解决什么问题

| 维度 | 客户需要解决的问题 | 重点核查 | 对采购判断的意义 |
|---|---|---|---|
| 运动能力 | 能否到达目标，并在所需姿态下连续操作？ | 自由度、关节活动范围、有效工作空间、定位表现、速度与节拍 | 决定任务可达性和规划难度，不能只比较最长伸展距离 |
| 负载与自重 | 装完整套末端后，还能完成多重、多快的搬运？ | 附件重量、重心、腕部力矩、负载曲线、臂重及动态工况 | 决定有效作业负载和整机集成代价 |
| 力控 | 接触后能否感知并稳定调整？ | 力感知方式、精度、响应、控制模式及接触任务实测 | 决定插拔、装配等任务的可行性和调试投入 |
| 末端适配 | 手、相机和传感器能否顺利装上并运行？ | 法兰、供电、通信协议、驱动、走线和工具标定 | 决定适配周期、附件成本和后续维护 |
| 控制开放 | 外部算法可以控制到哪一层？ | 指令类型、更新频率、延迟与抖动、反馈信号、接口限制 | 决定OEM能否接入自己的控制与模型体系 |
| 机器人学习 | 示教、采集、训练和真机部署能否连起来？ | 遥操映射、时间同步、数据定义、训练工具及真机部署案例 | 决定研发效率和模型适配工作量 |

六维不是固定权重的评分表。先定义任务的质量、节拍、接触和安装要求，再筛选满足必要条件的产品；不能用接口丰富抵消负载不足，也不能用重复定位精度替代接触任务验证。

<a id="motion"></a>

## 2. 运动能力：到得了，还要摆得好、动得顺

### 六轴与七轴

末端位姿包含三维位置和三维朝向。常见六轴机械臂在可达范围与非奇异条件下可以控制这六个维度；七轴增加运动冗余，可在保持末端位姿的同时调整肘部，为避障、避开关节限位和改善路径提供空间。七轴不自动意味着更高精度，也不能消除所有奇异位型。运动冗余与奇异的基础解释见 [Modern Robotics 5.3](https://modernrobotics.northwestern.edu/nu-gm-book-resource/5-3-singularities/)。

- **逆运动学（IK）**：由目标末端位置和朝向反算各关节的配置。
- **奇异位型**：某些姿态下，机械臂失去部分方向的瞬时运动能力；接近这类姿态时，小幅末端运动可能要求很大的关节速度。
- **选型含义**：验证整条任务路径、肘部空间与工具姿态，不仅检查起点和终点。

### 工作半径、精度与速度

工作半径只描述可达范围的一部分。某点虽然够得到，但可能接近关节限位、姿态受限，或装上工具后发生干涉，因此要检查实际安装条件下的有效作业空间。

重复定位精度衡量反复回到同一目标的一致性，绝对定位精度衡量实际位姿与目标位姿的偏差；两者不能混用。工具安装、标定和负载也影响实际任务结果。视觉或接触反馈可以补偿部分误差，但不能据此忽略机械臂本身的稳定性。

速度应落到完整任务节拍。固定产线关注合格吞吐；科研遥操可以更重视跟随、连续性和可控性，但仍须满足任务所需的响应速度。

<a id="payload"></a>

## 3. 负载与自重：比较完整末端配置下的能力

额定负载不是可抓取物品重量。灵巧手、六维力传感器、转接板、腕部相机和随动附件都要计入。可以先做质量层面的初筛：

> 抓取物品的质量余量 ≈ 额定负载 − 末端全部附件质量。

该式不能单独作为验收依据。还要核对厂商规定的重心、腕部力矩、惯量、姿态和运动条件；同样重量，重心离手腕越远，力矩负担通常越大。额定5公斤的臂挂上3公斤附件，并不保证在所有姿态和速度下都能再搬2公斤。

臂重的影响取决于安装场景。固定桌面更关注底座和支撑；移动底盘、双臂及人形本体还要考虑重心、惯量、承载和能耗。比较负载自重比时，也需统一工作范围、工具偏置和动态要求，不能单独凭比值判断产品优劣。

**向供应商索取：** 实际工具配置下的负载曲线、允许力矩与惯量、质量和重心说明，以及相应姿态和连续循环的测试条件。

<a id="force"></a>

## 4. 力控：手负责握持，臂负责接触中的位姿调整

以插接头为例，手要握稳接头，臂要找正位置和角度，并在碰到接口后退让、修正和推进。手部触觉与臂部力控承担不同职责，不能互相替代。

常见力感知途径包括关节力矩传感器和腕部六维力/力矩传感器。前者测关节受力信息，后者测腕部三个方向的力与三个方向的力矩；若信号由模型或电流估算，也应单独标注。不同测量位置、噪声、标定和补偿条件下的结果不能直接比较。

| 控制方式 | 直观理解 | 对应场景 |
|---|---|---|
| 阻抗控制 | 规定机械臂运动偏差与作用力之间的动态关系，可理解为设定软硬和阻尼 | 让接触具有合适的柔顺性 |
| 导纳控制 | 根据外力计算应产生的运动 | 拖动示教、受力后顺应移动 |
| 力位混合控制 | 在适当的不同方向或子空间分别控制运动与力 | 沿表面移动，同时保持法向接触力 |

力位混合控制的方向分工见 [Modern Robotics 11.6](https://modernrobotics.northwestern.edu/nu-gm-book-resource/11-6-hybrid-motion-force-control/)。上述任务例子用于解释方法，不代表某型号已经实现相应性能。

必须分开记录三类“快”：

| 概念 | 表示什么 | 不能据此直接推出 |
|---|---|---|
| 传感器采样频率 | 每秒取得多少次测量 | 整个机械臂具有同等频率的力响应 |
| 外部控制更新频率 | 外部程序每秒更新多少次指令 | 接触稳定性或实际力控带宽 |
| 力控带宽 | 闭环在一定条件下有效跟踪力变化或抑制扰动的频率范围 | 所有工具、负载和接触环境下的相同性能 |

评价力控要看“能感知、测得准、响应合适、能稳定调整”。具体任务中记录力误差、接触过冲、完成率、耗时和人工调整，而不是只列传感器频率。

<a id="integration"></a>

## 5. 末端适配：装得上、电够用、能通信、线不碍事

- **机械连接**：核对法兰、孔位、工具尺寸和活动空间。新增转接板会改变重量、长度和重心，应重新核对负载。
- **供电**：核对电压、连续与峰值供电能力，以及多设备同时工作的需求。
- **通信与软件**：CAN、RS-485、Ethernet等接口名称只说明部分条件，还须匹配协议、驱动、数据定义和版本。
- **走线与维护**：检查臂内和腕部走线、弯折余量、关节旋转范围及更换便利性。内走线也需核实可用通道和维护方式。

宣传页不足以回答这些问题，应结合用户手册、接口定义和CAD图，在完整末端配置下验证。末端适配会反过来改变运动空间和负载，六个维度不能割裂评估。

<a id="control"></a>

## 6. 控制开放：能发什么、多久发一次、能读回什么

“支持二次开发”或“支持ROS”不能单独说明底层开放程度。应逐项核对：

| 检查项 | 需要明确的内容 |
|---|---|
| 指令权限 | 目标位姿、关节位置、关节速度、末端速度、关节力矩等哪些可用；是否可连续更新 |
| 接口性能 | 各接口分别支持的更新频率、实际延迟与抖动、丢包与超时行为 |
| 状态反馈 | 关节角度、速度、力矩、末端位姿和受力、时间戳、故障及执行状态 |
| 控制分工 | 外部程序、厂商控制器和全身控制如何分工，指令是否被插值、滤波或限幅 |
| 工程条件 | 适用硬件、固件和SDK版本，主机与网络要求，授权及支持范围 |

作为可核查的接口示例，Franka的libfranka文档分别说明运动指令、关节力矩控制和状态反馈，并描述1 kHz实时循环及通信约束。这说明接口层级与运行条件需要一起核对，不能推广为所有支持SDK的产品都具备相同能力。[Franka FCI官方文档](https://frankarobotics.github.io/docs/doc/libfranka/docs/overview.html)

高频接口不代表机械臂物理运动更快，也不要求VLA等上层模型以同样频率推理。模型输出如何变成连续控制指令，应结合[模型与控制分层](../02_models/model-report.md#scope)评估。

<a id="learning"></a>

## 7. 机器人学习：把示教、数据与部署连起来

机器人学习的价值链可按三个问题检查：

1. **人好不好教。** 遥操输入怎样映射到臂和手，是否需要大量标定，动作是否连续，失败和接管怎样记录。
2. **数据好不好训。** 相机、臂、手、力和触觉是否时间对齐，坐标、单位、动作含义与设备版本是否一致，数据能否被目标训练工具使用。
3. **模型好不好回到真机。** 是否已有适用版本的驱动、模型适配和部署案例，换臂、换手或换相机后需要重新完成哪些工作。

“能够存下数据”不等于“数据可训练”，“已有训练脚本”也不等于“能在本机稳定部署”。力与触觉等模态是否必要，应由任务以及训练和部署效果决定，不能预设所有VLA项目都必须使用相同配置。

生态可能减少重复开发，但这属于需要验证的效率收益。应比较达到同等任务要求所需的工程人天、调试时间和有效数据投入，而不是仅按开源项目数量判断。硬件销售也不自动赋予供应商客户数据的使用权。

<a id="scenarios"></a>

## 8. 场景决定优先级

| 场景 | 优先核查 | 采购时容易遗漏的条件 |
|---|---|---|
| 固定工位抓取、搬运 | 有效工作空间、负载、稳定性和节拍 | 完整路径及工具干涉；六轴可能已经够用 |
| 插拔、装配、擦拭、打磨 | 力控、工具姿态调整和接触任务表现 | 精度与力控需配合验证，不能互相替代 |
| 遥操、数据采集、模型研究 | 运动冗余、开放接口、同步、训练与部署工具 | 七轴和力反馈是否值得取决于任务；采集设备不自动计入人形装机 |
| 挂载灵巧手及多传感器 | 附件后的负载余量、腕部力矩、供电和通信 | 转接板、走线、标定与版本兼容 |
| 装在人形或移动本体上 | 自重、尺寸、功耗、动态负载和整机协同 | 肩肘腕布局、双臂干涉、移动条件下的可靠性 |

科研演示成功后，进入生产应用仍需补充长期循环、质量、维护与交付验证。总体选型原则是满足任务必要条件，再比较完成任务的总成本。

<a id="sourcing-implications"></a>

## 9. 怎样接入协作厂商供臂的市场分析

以下是分析推断及验证方向，不是新增市场份额事实。

**第一，协作经验可以迁移，但产品需要按人形工况重新验证。** 运动控制、力控、关节集成、制造和测试经验有复用价值；轻量化、尺寸、走线和全身控制仍可能要求重新设计。是否形成优势，要看同任务下适配周期和交付结果。

**第二，科研采集与本体装机对应不同的采购侧重点。** 前者更关注开放接口、同步和开发生态；后者还需重点比较重量、尺寸、成本、可靠性及量产供货。两类需求按[用途边界](arms-and-oem-sourcing.md#scope)分开，不能以科研平台的使用热度推算人形OEM装机份额。

**第三，集成效率可能影响中标和复购，但必须以项目证据验证。** 硬件报价应与附件、适配开发、数据整理、部署和维护的投入一起比较。接口与工具若能跨客户复用，可能降低交付成本；若每个客户仍需重做，相关平台优势就需要重新评估。

对应的传导链是：

> 客户任务 → 六维能力与系统适配 → 达标所需的时间和总成本 → 自研/外购及供应商选择 → 验收、稳定运行与复购。

这条链解释产品能力如何影响[采购路径](arms-and-oem-sourcing.md#sourcing)，不替代[订单到交付的验证](arms-and-oem-sourcing.md#demand)。

<a id="validation"></a>

## 10. 下一步取什么证据

| 验证问题 | 最有价值的材料 |
|---|---|
| 装好工具后是否真正能干目标任务？ | 型号、版本、安装姿态、完整末端配置、负载重心及全路径测试记录 |
| 力控和控制接口是否满足算法需要？ | 对应版本的接口文档、实测日志、接触任务结果及厂商/客户控制分工 |
| 数据是否可直接用于训练并回到真机？ | 脱敏的数据字段和同步说明、训练到部署流程、同配置复现结果 |
| 外购是否减少客户的工程投入？ | 同等任务要求下，从集成到验收的人天、时间、故障和维护记录 |
| 研发优势能否转化为持续供货？ | 分机型验收、同代复购、下一代选型和配置变化原因 |

指标记录粒度为“型号/版本—安装配置—任务—工况—测试样本—结果—证据来源”。缺失项写未知，不以宣传参数填入实测栏。关键缺口进入[待验证问题](../04_tracking/questions.md)，可比较的项目结果进入[统一指标](../04_tracking/metrics.md)。

## 来源与适用限制

本篇由机械臂六维选型讨论整理为研究框架，公开技术资料仅用于核对基础概念与接口示例。口述材料中的未核实品牌评价、数据集名称和价格片段不作为供应商事实或采购推荐。

- [Modern Robotics 5.3：运动冗余与奇异](https://modernrobotics.northwestern.edu/nu-gm-book-resource/5-3-singularities/)：教材解释，不构成某型号性能实测。
- [Modern Robotics 11.6：力位混合控制](https://modernrobotics.northwestern.edu/nu-gm-book-resource/11-6-hybrid-motion-force-control/)：控制原理，不构成任务成功率证据。
- [Franka FCI：libfranka接口概览](https://frankarobotics.github.io/docs/doc/libfranka/docs/overview.html)：厂商文档；实际使用需核对型号、版本和系统条件，不能用来推断其他厂商能力。

本次未开展跨厂商实测；六维优先级、集成成本与采购传导属于研究框架和分析判断。新取得的厂商数据按[研究方法与证据标准](../research-method.md)补充。
